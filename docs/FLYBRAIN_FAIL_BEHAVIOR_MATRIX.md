# FlyBrain Fail Behavior Matrix

This matrix defines the required fail-open vs fail-closed behavior for FlyBrain harness jobs and Loci memory operations across the lifecycle. It is normative for implementers and reviewers: safety-critical checks must stop the run, while observability-only or legacy-compatibility faults may degrade without converting partial evidence into a trusted conclusion.

## Lifecycle matrix

| Lifecycle stage | Fail-closed / hard stop | Degraded-but-allowed / fail-open | Expected operator / action response | Mapping to current implementation and docs |
|---|---|---|---|---|
| enqueue | Reject any queued FlyBrain job when `LOCI_FLYBRAIN_STORAGE_ROOT` is missing, relative, drive-root, UNC, or resolves through a symlink/reparse point. Reject queued writes outside the allowlisted root and reject destructive or cleanup tasks without an explicit subpath under the root. | Noncritical telemetry or logging can fail without blocking enqueue. A job may remain in `dry-run`/`planned` state if it is still exploratory and the scope is intentionally constrained. | Stop scheduling the job, fix configuration, and re-run preflight. If the issue is noncritical, keep the item as planned or dry-run only, with explicit caveats in the run log. | `mcp/flybrain_harness_storage.py` requires `LOCI_FLYBRAIN_STORAGE_ROOT`, rejects relative roots, drive roots, reparse traversal, and abnormal root paths. `docs/FLYBRAIN_WRITE_PATH_SAFETY_POLICY.md` says: “Any failed check is a hard failure (no fail-open behavior).” |
| claim | Hard-stop claim publication when a FlyBrain fact overgeneralizes across dataset, sex, stage, anatomy, or evidence family without supporting scope. Reject missing dataset/version/query scope for any FlyBrain-derived claim. Reject `model_asserted` findings without independent evidence. | Legacy data with partial provenance may remain in memory but only as degraded/limited evidence. A missing noncritical audit record or a soft warning does not justify claiming universal truth. | Narrow the claim to the exact dataset, version, query path, or evidence family used. If it cannot be narrowed, do not publish it as a final answer. | `docs/FLYBRAIN_DATA_PROVENANCE_GUIDANCE.md` requires dataset scope, query semantics, result contract, and scope tags. `mcp/provenance_firewall.py` enforces that `model_asserted` evidence requires independent human/tool/deterministic evidence. `mcp/replay_fingerprint.py` creates a canonical replay fingerprint for FlyBrain provenance envelopes. |
| execute | Stop immediately on path-guard failure, destructive path escape, budget hard-stop (`>= 200 GB` in policy), freeze trigger, manifest validation failure, or writer errors that would create unverified artifacts. | Read-only diagnostics, dry-runs, and non-writing validation are allowed while a run is paused for budget or freeze review. A failed append to the event log or other noncritical telemetry must not block the run. | Pause the job, move to read-only validation, and require corrective action or operator override before resuming writes. Capture the deny reason in logs. | `docs/FLYBRAIN_WRITE_PATH_SAFETY_POLICY.md` requires strict allowlist containment and destructive-op guards. `docs/FLYBRAIN_OPERATOR_TRAINING_CHECKLIST.md` defines freeze triggers and Level 1-3 write freezes. `mcp/server.py` explicitly documents that event-log failure is fail-open: “Never let event log failures block memory operations.” |
| persist | Do not treat a persisted FlyBrain finding as valid evidence if provenance is missing or replay scope does not match the evidence. Reject persist if the manifest/file integrity or replay fingerprint cannot be validated. Claims derived from `model_asserted` evidence without independent support must not become durable “curated truth.” | Legacy findings without explicit provenance may be stored as degraded entries, but they must remain clearly bounded and not promoted to a verified conclusion. A failed noncritical audit append should not block storing the primary finding. | Persist as degraded, add the missing provenance envelope, and quarantine the artifact until replay or manifest checks pass. | `mcp/tests/test_flybrain_provenance_envelope.py` verifies that FlyBrain provenance and a 64-hex replay fingerprint persist to `investigation_store` and survive recall. `docs/FLYBRAIN_HARNESS_MANIFEST_PROVENANCE_SCHEMA.md` requires path, hash, scope, and version checks before artifact use. |
| promote | Block promotion if manifest/hash checks fail, if the artifact is stale (`next_check_due` in the past or not revalidated), if the replay fingerprint does not match the execution context, or if the storage/budget freeze policy is still active. | Promotion may remain in a “degraded, not promoted” state while operators inspect evidence. Read-only checks can continue during a freeze. | Freeze candidate promotion, isolate the artifact, and require fresh manifest/checksum/replay validation before release. | `docs/FLYBRAIN_HARNESS_MANIFEST_PROVENANCE_SCHEMA.md` says readers must reject empty or stale manifests and quarantine on any mismatch. `docs/FLYBRAIN_OPERATOR_TRAINING_CHECKLIST.md` requires promotion gates and freeze policy sign-off before candidate promotion. |
| complete | Final completion is not allowed when the claim is broader than the supported dataset scope, the evidence cannot be replayed, or unresolved provenance/integrity gaps remain. Completion must not silently flatten dataset differences or claim universality without proof. | A run may complete in `read-only`, `degraded`, or `limited-scope` mode if the operator documents the caveats. The completion is only partial, not a verified general fact. | Leave a final note with exact scope, caveats, and the missing validations. Operators must record what would need to be revalidated before the result becomes publishable. | `docs/FLYBRAIN_GUIDE.md` states that a result is trustworthy only when its evidence path remains traceable. `docs/FLYBRAIN_DATA_PROVENANCE_GUIDANCE.md` requires scope-limited wording and explicit dataset/version boundaries. |

## Normative rules

1. Safety-critical path checks are fail-closed. Missing root, relative path, symlink/reparse traversal, drive-root targeting, destructive path escapes, and any policy gate violation stop the run.
2. Provenance and replay are fail-closed for reused evidence. A FlyBrain fact without dataset/version/query scope is not promotable to a trusted conclusion. The evidence path must be traceable.
3. Observability-only faults are fail-open. Event-log append failures, telemetry issues, or legacy memory records may degrade without stopping the workflow, but only if the result is explicitly marked as degraded and is not represented as validated.
4. Model-generated conclusions are gated by independent evidence. `mcp/provenance_firewall.py` denies a `model_asserted` claim unless there is human/tool/deterministic evidence supporting it; the intentional failure mode is to fail open only on unexpected runtime exceptions, not on missing evidence.
5. Promotion and completion are not the same as validation. A job may complete in degraded mode, but it may not be released as a trusted result until replay, integrity, and scope checks pass.

## Actionable implementation expectations

- Validate the configured storage root before all write/delete operations.
- Require a FlyBrain provenance envelope whenever a result is derived from `search_terms`, `get_term_info`, `query_connectivity`, `run_query`, or similar tool outputs.
- Treat `replay_fingerprint`, `dataset_scope`, and `result_contract` as required metadata, not optional extras.
- Never allow a promotion event to keep state when manifest or checksum validation fails.
- If a check cannot complete, record the degraded state explicitly and preserve the exact scope limits in the operator notes.

## Grounding summary

This document is grounded in the current repo behavior and FlyBrain docs:

- Storage safety: `mcp/flybrain_harness_storage.py`, `docs/FLYBRAIN_WRITE_PATH_SAFETY_POLICY.md`, `docs/FLYBRAIN_HARNESS_STORAGE_LAYOUT.md`
- Provenance and replay: `mcp/replay_fingerprint.py`, `mcp/provenance_firewall.py`, `docs/FLYBRAIN_DATA_PROVENANCE_GUIDANCE.md`, `docs/FLYBRAIN_HARNESS_MANIFEST_PROVENANCE_SCHEMA.md`
- Loci memory behavior: `mcp/server.py`, `mcp/tests/test_flybrain_provenance_envelope.py`
- Operator gates: `docs/FLYBRAIN_OPERATOR_TRAINING_CHECKLIST.md`, `docs/FLYBRAIN_GUIDE.md`

The intended boundary is simple: keep the run safe and replayable, permit degradation only for diagnostics and legacy compatibility, and never silently upgrade a partial result into a general fact.
