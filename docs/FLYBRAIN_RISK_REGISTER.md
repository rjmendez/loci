Severity scale: **Critical** (hard stop), **High** (gate block until fixed), **Medium** (proceed only with explicit containment and tracking).

| ID | Domain | Risk | Owner | Severity | Trigger conditions | Mitigations / preventive controls | Stop/Go response |
|---|---|---|---|---|---|---|---|
| FB-R01 | Technical safety | Path escape or destructive write outside allowlisted root | Harness storage owner | **Critical** | Any candidate path fails containment/reparse-point checks; any delete/move target resolves to root, drive root, or outside `LOCI_FLYBRAIN_STORAGE_ROOT` | Mandatory `validate_flybrain_path(...)` gate before all filesystem I/O; denylist enforcement; dry-run for cleanup; no direct shell delete on unvalidated paths | **Stop:** abort run immediately, no side effects beyond logs. **Go:** only after path contract passes for all staged operations. |
| FB-R02 | Data integrity | Corrupt/partial artifacts promoted (size/hash mismatch, parse failure) | Integrity owner | **Critical** | Missing required files, `.partial/.tmp` markers, size mismatch, hash mismatch, archive parse failure, verification status `quarantined` | Ordered verification lane (presence -> size -> partial checks -> hash checks); quarantine failed payloads with `quarantine_event.json`; keep last-known-good promoted data active | **Stop:** block promotion/sync, quarantine payload, keep prior active pointer. **Go:** only when fresh fetch revalidates to `verified`. |
| FB-R03 | Technical reliability | Promotion pointer integrity failure (candidate not atomically promoted or active store mutation) | Graph promotion owner | **High** | Promotion metadata missing/incomplete; active pointer not atomically updated; in-place mutation attempt on active graph | Blue/green candidate builds; atomic promotion metadata writes; smoke tests before promotion; explicit promotion state checks | **Stop:** freeze promotion lane and continue on prior active graph only. **Go:** after promotion state passes structural + smoke checks. |
| FB-R04 | Operational capacity | Storage budget exhaustion causing unsafe cleanup or failed runs | Operations on-call | **High** | Usage reaches watch/soft/critical/hard thresholds (150/160/180/200 GB) or projected writes breach caps | Budget telemetry in preflight; retention workflow (clear cache, archive stale snapshots, prune scratch); freeze nonessential writes at critical threshold | **Stop:** at hard stop (>=200 GB) block nonessential writes; at critical (>=180 GB) require explicit override. **Go:** only after usage returns under policy threshold with recorded cleanup actions. |
| FB-R05 | Pipeline control | Run-mode or milestone bypass (execute without dry-run/plan gates) | Rollout owner | **High** | Execute invoked without successful M0/M1 artifacts, unapproved dataset scope/pins, or failed preflight/policy checks | Sequential milestone enforcement M0->M1->M2->M3; mandatory plan artifacts and idempotency keys; fail-closed on scope/pin mismatch | **Stop:** block auto-advance and execute lane. **Go:** only when prior milestone exit criteria artifacts are present and valid. |
| FB-R06 | Scientific validity | Overgeneralized claims beyond dataset/sex/stage/anatomy scope | Scientific provenance owner | **High** | Output language broadens dataset-local evidence to universal claims; missing scope tags (`sex`, `stage`, `anatomy`) | Enforce provenance envelope and claim-tier wording; require explicit scope fields on every stored claim; cap language to dataset/version-local unless matched corroboration exists | **Stop:** do not store/promote claim as general finding. **Go:** either narrow wording to scoped claim or add direct corroborating evidence. |
| FB-R07 | Scientific interpretation | Query semantics misread as biological certainty (`count_status`, grouped counts, heavy filters ignored) | Scientific QA owner | **Medium** | `count_status != exact` treated as complete; `group_by_class=true` totals interpreted as pairwise exact edges; constrained filters omitted in summary | Mandatory result-contract capture (`count`, `count_status`, warnings, filters, group mode); rerun sanity sample when needed; explicit caveat wording | **Stop:** block high-confidence assertion and publication language. **Go:** include semantics caveats or rerun with corrected query settings. |
| FB-R08 | Reproducibility | Version-pin drift or replay fingerprint drift causes unstable conclusions | Provenance + release owner | **High** | Dataset version differs from pinned contract; replay hash/structural result drift beyond accepted contract | Pin `hb`/`fw` version IDs; persist replay fingerprint + manifest references; deterministic query pack reruns; drift checks before promotion | **Stop:** hold decision and downgrade confidence; schedule re-baseline. **Go:** after drift is explained and new baseline approved/versioned. |
| FB-R09 | Operational resilience | Resume/idempotency failure causes duplicate writes, partial state, or unrecoverable reruns | Pipeline owner | **Medium** | Interrupted run cannot resume deterministically; repeated stages produce inconsistent artifacts; missing stage-state/idempotency keys | Deterministic stage fingerprints and persisted stage state; resumable byte-range fetch; retry policy only for transient errors | **Stop:** pause pipeline and retain current active data; investigate idempotency state. **Go:** after resume path reproduces expected stage outputs without divergence. |
| FB-R10 | Evidence integrity | Remote fallback results presented as local hb/fw evidence | Query adapter owner | **High** | Local miss silently falls back to remote without explicit provenance/scope tag; mixed local/remote result bundles unlabeled | Explicit remote fallback adapter boundary; mandatory `access_method` + dataset scope tags; separate local vs remote result lanes | **Stop:** block response storage/promotion as local evidence. **Go:** only when remote scope is explicit and claims are labeled as non-local evidence. |
| FB-R11 | Auditability | Missing or incomplete logs/artifacts prevent post-incident reconstruction | Observability owner | **Medium** | Missing `preflight.json`, `plan.json`, stage-state files, or query pack/result artifacts for executed runs | Required log artifact set per run; alerting on missing run artifacts; retention policy for run logs and quarantine evidence | **Stop:** treat run as non-compliant for rollout sign-off. **Go:** after artifact set is complete and readable. |

## Phase-1 stop/go summary

- **Hard-stop conditions:** any FB-R01/FB-R02 trigger, promotion state integrity failure, unapproved scope/pins, manifest schema failure, or integrity verification failure.
- **Proceed-with-containment conditions:** medium risks may proceed only with explicit caveats, recorded mitigations, and no violation of hard-stop controls.
- **Go to wider rollout:** only after phase-1 experiment acceptance criteria pass (`+20pp` scope-complete uplift, no overclaim increase, zero integrity/promotion hard-stop errors, deterministic replay contract preserved).
